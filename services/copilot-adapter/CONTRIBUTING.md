# Contributing to the Copilot adapter

The adapter is contract-first and generated-first. The steps below use paths
relative to the public module root containing `go.mod`.

## 1. Change the contract before anything else

- The HTTP surface is [`openapi.yaml`](openapi.yaml); the intent behind it is
  [`application.yaml`](application.yaml). Edit those first, keep the style
  (operationIds, the shared `Error` schema, UUID ids, RFC 3339 `Z` timestamps,
  named enums, `required` everywhere it is true, `additionalProperties: false`,
  `limit` + `cursor` paging), and lint with redocly in the node container.
- Tunables are declared, never consts in source: the adapter's config is the
  Liquid Proto contract in [`proto/`](proto/) with defaults in
  [`config/defaults.json`](config/defaults.json), surfaced through `WithConfig`.
- The schema is only the migration files under
  [`store/migrations`](store/migrations); queries are
  [`store/queries.sql`](store/queries.sql). Nothing in Go declares a table.

## 2. Generate everything that can be generated

Use Go 1.26.5, Docker and Node 22. Install the UI's locked dependencies before
regenerating its TypeScript projections:

```bash
bash services/copilot-adapter/generate.sh write        # openapi.yaml -> gen/api
bash services/copilot-adapter/store/generate.sh write  # migrations + queries -> storedb
bash services/copilot-adapter/proto/generate.sh write  # config + validation
go generate ./services/copilot-adapter/...             # mocks, views and widgets
(cd services/copilot-adapter/ui && npm ci && npm run gen)
```

The three shell generators have a `check` mode that regenerates into a temporary
directory and diffs. The UI has `npm run gen:check`; verify `go generate`
outputs with a source diff. Never hand-edit generated output.

## 3. Only then write the boundary

- The service is a library: `NewCopilotAdapter(...Option)` and
  `Register(router gin.IRouter)` are its whole surface. It never opens a
  listener, never has a `cmd/`, never ships a Dockerfile; the binary in
  [`app/csf/cmd`](../../app/csf/cmd) owns those.
- Seams are interfaces the service *accepts*: `ICopilotBridge` (the SDK) and
  `IStore` (sqlc's generated `Querier`). Constructors return concrete types and
  are named for what they build (`NewCopilotAdapter`, `NewCopilotBridge`).
- One goroutine owns each piece of mutable state (the session registry, each
  session's projection); no mutex-guarded state machines.
- Streaming goes through `pkg/httpserver`'s event-stream helpers; shared
  headers and middleware live there, not here.
- Nullable columns are guregu/null values and pointer uuids by sqlc override:
  read `.Ptr()`/`.ValueOrZero()`, write `null.TimeFrom`/`null.StringFrom`, never
  a private Null* helper. Statuses, kinds and codes come from the generated
  enums or one named constant (CS-13); constructors name what they build (CS-12).
- Handlers return `fail(status, code, message)` or `lookupFailure(...)`; one
  strict middleware renders the `Error` body. Never spell a response envelope.
- New operations you cannot implement yet answer 501 with the `Error` shape
  (`code: not_implemented`) so the contract stays honest.

## 4. Tests

- Ginkgo v2 + Gomega, dot-imported; gomock doubles generated by mockgen.
- Unit specs live beside the code; integration specs under
  [`integration/`](integration/) run the real service on `pkg/pgmem`
  with the real migrations and a mocked CLI, driven through the generated
  client.
- Waits use `pkg/patience` with a named budget.
- UI: Vitest + Testing Library, in the node container.

## 5. Gates before you push

```bash
gofmt -l ./services/copilot-adapter
go vet ./services/copilot-adapter/...
go test -race -count=1 -p 4 ./services/copilot-adapter/... ./pkg/sqlmigrate/... ./pkg/httpserver/...
bash services/copilot-adapter/generate.sh check
bash services/copilot-adapter/store/generate.sh check
bash services/copilot-adapter/proto/generate.sh check
bash pkg/scripts/check-test-style.sh
(cd services/copilot-adapter/ui && npm run gen:check && npm test -- --run && npm run build)
```

The public repository's [CI workflow](../../.github/workflows/ci.yml) also
checks the Go module and Bazel metadata.

## 6. See it running

Follow the [public host instructions](README.md#run-it-as-a-plain-binary) to
configure PostgreSQL, a repository and the Copilot CLI, then mount the built
UI in the CSF host. Verify UI changes in a browser as well as through tests.

## 7. Source changes

Follow the repository's [source and publication policy](../../AGENTS.md) for
changes to the shared package. Keep source changes and regenerated projections
together; exclude local credentials, `node_modules`, `dist` and Python bytecode.
