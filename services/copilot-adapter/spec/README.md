# Copilot CLI SDK protocol — reference spec

[`generate_sdk_openapi.py`](generate_sdk_openapi.py) produces a local
**reference** OpenAPI 3.1 document from an installed Copilot CLI's JSON schemas.
The derived document and upstream schemas are not included in this public
snapshot. The reference describes the JSON-RPC protocol used over stdio; it is
not a Go code-generation input. The adapter's own HTTP contract is
[`../openapi.yaml`](../openapi.yaml).

## Provenance

The generator was recorded against the following CLI package and schema
layout; the public Go module pins `github.com/github/copilot-sdk/go` v1.0.11:

| Item | Value |
|---|---|
| Source files | `schemas/api.schema.json`, `schemas/session-events.schema.json` |
| Shipping package | `@github/copilot` **1.0.80** (also present, identical layout, in 1.0.34) |
| Schema dialect | JSON Schema draft 2019-09 |
| Upstream repo | `github.com/github/copilot-cli` |

These are the same files the Go SDK is generated from: `rpc/zrpc.go` in
`copilot-sdk/go@v1.0.11` opens with

```
// Code generated by scripts/codegen/go.ts; DO NOT EDIT.
// Source: api.schema.json
```

The generator reads those two source schemas directly. Supply the schema
directory from your own installed CLI; its location depends on your installation.

## How it is generated

With Python 3 and PyYAML available, run from the public module root. Replace the
schema path with the directory containing the two JSON files:

```bash
COPILOT_SCHEMAS=/absolute/path/to/installed/copilot/schemas
python3 services/copilot-adapter/spec/generate_sdk_openapi.py \
  --schemas "$COPILOT_SCHEMAS" \
  --out /tmp/copilot-sdk.openapi.yaml

# deterministic regeneration check (same command, --check): diffs instead of writing
python3 services/copilot-adapter/spec/generate_sdk_openapi.py \
  --schemas "$COPILOT_SCHEMAS" \
  --out /tmp/copilot-sdk.openapi.yaml --check
```

## Coverage

The recorded CLI 1.0.80 projection covered:

| Thing | Modeled | Found in source |
|---|---|---|
| JSON-RPC methods → `POST /rpc/<method>` | **341** | 341 (`server` 84, `session` 233, `clientSession` 19, `clientGlobal` 5, across arbitrarily nested namespaces) |
| Session event kinds in the `SessionEvent` discriminator | **116** | 116 union members carrying a `type` const |
| Component schemas | **1464** | 1045 api + 461 event definitions, 43 byte-identical duplicates collapsed |

No method, event kind or definition was skipped in that recorded projection.
Different installed schema versions may produce different counts.

## Verbatim vs modeled

- `x-provenance: published` — every path, operation and component schema. Their
  bodies, descriptions, enums and required sets are the upstream JSON Schema
  verbatim; only the *shape* around them is ours.
- `x-provenance: modeled-from-go-sdk-v1.0.11` — exactly one schema,
  `JsonRpcError`. The CLI schemas describe params and results but not the
  JSON-RPC 2.0 envelope, so the error object is modeled from the SDK's transport.

Normalizations applied by the generator, all mechanical:

1. `#/definitions/X` → `#/components/schemas/X`, including the api schema's
   cross-file `session-events.schema.json#/definitions/X` pointers.
2. The two schemas share 48 names. 43 are byte-identical and collapse; the 5 that
   genuinely differ (`Attachment`, `ContextTier`, `ReasoningSummary`,
   `ShutdownType`, `Verbosity`) keep the api meaning under the plain name and the
   event meaning under `<Name>SessionEvent`, so neither is lost.
3. The CLI's own schema annotations (`stability`, `internal`, `rpcMethod`, …) are
   legal JSON Schema but illegal OpenAPI, so they move to `x-`-prefixed
   extensions rather than being dropped. Method-level ones surface as
   `x-stability` / `x-internal` on the operation.
4. `SessionEvent` gains an explicit `discriminator` on `type` with a mapping from
   each event's `type` const, so a consumer dispatches instead of trial-decoding
   116 alternatives.
5. `security: []` at the root, because a stdio subprocess has no transport
   authentication — an empty set stated rather than omitted.

## Reading it

Each `POST /rpc/<method>` path stands for one JSON-RPC method. The request body
is that method's `params` member, the `200` body is the `result` member, and the
`default` response is the JSON-RPC `error` member. `servers` names
`stdio://copilot` to make it obvious this is not a network API. Operations are
tagged by group (`server`, `session`, `clientSession`, `clientGlobal`); the two
`client*` groups are **reverse** calls — the CLI calling the SDK client — which
is where tool invocation, hooks, permission prompts, user input and plan-mode
round-trips live.

## Lint

```bash
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -e npm_config_cache=/tmp/npm \
  -v /tmp/copilot-sdk.openapi.yaml:/spec/copilot-sdk.openapi.yaml:ro \
  -w /spec node:22-bookworm \
  bash -c 'npx --yes @redocly/cli@1.34.3 lint copilot-sdk.openapi.yaml'
```

The recorded check produced **0 errors, 526 warnings**. Both warning classes arise from describing a
JSON-RPC protocol in an HTTP vocabulary and are not defects to fix:

- `operation-4xx-response` (341, one per method): JSON-RPC has no status codes.
  Every failure arrives as the `error` member, which the spec models once as the
  `default` response on every operation.
- `no-unused-components` (185): the source schemas define shared vocabulary that
  is only reachable through `anyOf` branches or is exported for SDK consumers
  rather than referenced from a method. Dropping them would make the document a
  worse reference than the schema it projects.

## How the adapter contract relates to this

This document describes the **upstream** the adapter talks to; it is not the
adapter's own API. The adapter's [HTTP contract](../openapi.yaml) is the
smaller surface that `../generate.sh` already generates Go bindings from.
The local reference is never a codegen input. Its
job is to let a reader (or a UI, or a later generator) answer "what can the CLI
actually do, and what exactly does that call take and return" without reading a
1 MB generated Go file, and to give the adapter's authors an exact,
version-pinned name for every method and event kind they choose to expose or
deliberately leave out.
