# CSF documentation compiler and generation metrics

| File | Responsibility |
|---|---|
| `architecture.csf` | Authored names, plain-language definitions, diagram structure, and target documents. |
| `grammar.ebnf` | Grammar of this documentation language. It does not describe the controller expression language. |
| `compiler.ml` | OCaml parser, reference checks, fixed Mermaid renderer, and file generation. |
| `compiler_test.ml` | Native parser-to-file tests, including rejected input and generation drift. |

The compiler uses this module's pinned OCaml 5.3.0 toolchain and standard
library. It accepts structured flowcharts only. Node and group names come from
term definitions; edges optionally carry a plain-language relationship. Nodes
show their declared existing/planned status. Existing edges are solid and planned
edges dotted. These are documentation statements, not runtime verification.

This directory owns CSF's documentation language and diagrams; `tools/csf-language` is a generated root compatibility mirror, so edit this canonical source. The generated human reference is written directly to `csf/docs/generated/ontology_cgen.md`.
The separate [architecture compiler](../architecture/README.md) checks typed
process/scope declarations against selected Go source. These tools have distinct
inputs and guarantees; documentation rendering does not perform source checks.
The existing dependency checker is at `tools/gorilla_mux_lint`; both use
the root `MODULE.bazel` toolchain. No second OCaml installation or long-running
process is introduced. The controller's arithmetic model still lives in
`research/brain-spine/proof`; this compiler does not replace it.

The compiler and its OCaml, opam, and Tree-sitter inputs live in this exported
module. Run these commands from the standalone `candace/` root; the monorepo
workflow runs the same compiler there. Packaging-specific README diagrams are
outside this compiler's output set and remain owned by the packaging docs.

```sh
CANDACE_BAZEL_CACHE=/tmp/candace-csf-bazel-cache \
  bash tools/bazel.sh --batch build //csf/compiler/language:generate --lockfile_mode=error
bazel-bin/csf/compiler/language/generate.exe --root "$PWD" write
CANDACE_BAZEL_CACHE=/tmp/candace-csf-bazel-cache \
  bash tools/bazel.sh --batch test //csf/compiler/language:tests --lockfile_mode=error
bazel-bin/csf/compiler/language/generate.exe --root "$PWD" check
```

Each declared document must already contain its named sections, with opening
`<!-- csf:diagram NAME -->` and closing `<!-- /csf:diagram NAME -->` markers on
separate lines. The compiler replaces the section contents and preserves other
bytes. Every declared section must occur exactly once; nested, undeclared,
missing, or malformed markers fail. Mermaid fences outside these sections fail,
including backtick, tilde, indented, blockquoted, and list-contained fences.
Raw HTML elements with a `mermaid` class also fail, including multiline tags.

All source and target documents are parsed and validated before any output is
written. Document paths stay within the selected root and cannot use symlinks.
Writes replace changed files individually through temporary files in the same
directory. A filesystem failure during replacement can leave earlier files
updated; rerunning generation repairs that state. Check mode writes nothing and
fails if any generated byte differs. Files not declared as documents are outside
the handwritten-Mermaid check.

## Native generation percentages

The same executable has a read-only `metrics` command. Its OCaml library reads
only the files listed in an archive receipt; it does not walk the repository,
inspect Git, or discover build caches. Code and Markdown have separate
numerators and denominators. OCaml `.ml` and `.mli` files are excluded from both
code counts: the generator language is outside this metric's policy, whether
a file is generated or non-generated. They contribute to `excluded_files`,
as do code files under the exact archive prefix `candace/pkg/gotth/` (the entire
gotth-live package, including generated files). These exclusions do not apply to
docgen: Markdown under that prefix keeps its independent calculation. The code
percentage therefore describes the selected corpus, not all shipped code.

```sh
# Build once with the existing pinned toolchain.
CANDACE_BAZEL_CACHE=/tmp/candace-csf-bazel-cache \
  bash tools/bazel.sh build //csf/compiler/language:generate --lockfile_mode=error

# ROOT is an extracted archive or prepared workspace, not an implicit checkout scan.
bazel-bin/csf/compiler/language/generate.exe --root /path/to/archive metrics
bazel-bin/csf/compiler/language/generate.exe --root /path/to/archive metrics \
  --manifest /path/to/selected-receipt.json
```

The default manifest is `ROOT/SOURCE_RECEIPT.json`; its `files` array supplies
`path` and `sha256` for each selected file. Duplicate JSON member names use the
last value, matching the legacy calculator; repeated selected file paths still
fail validation. Comments, unquoted keys, and unescaped string controls are
rejected. Python-compatible `NaN` and `Infinity` values in unused metadata do
not affect selection. The pinned Yojson parser rejects malformed high-surrogate
escapes even in unused metadata, where Python's decoder permits them; this is
a stricter input limit, not a different counting rule.

The JSON result contains:

| Output | Meaning |
|---|---|
| Top-level `codegen_percentage` | Selected code files, including source comments and blank physical lines. |
| `excluded_code_extensions`, `excluded_code_paths` | Declared code exclusions: `.ml`, `.mli`, and the `candace/pkg/gotth/` prefix. |
| `documentation` (`metric: docgen_percentage`) | Selected Markdown counted separately. |
| `generated_lines`, `non_generated_lines`, `total_lines` | Counts for each corpus, each code language, and each Markdown file. |
| `generated_percent`, `non_generated_percent` | Independently rounded to two decimal places; both `null` when the denominator is zero. |
| `generated_files`, `non_generated_files` | Whole code-file classifications; empty files still count as files. |
| `modified_files` | Selected code/Markdown whose current bytes differ from their receipt hash. Their current bytes are measured. |
| `handwritten_lines`, `handwritten_files` | Compatibility aliases for the non-generated counts. They do not identify an author. |

Code files are generated only when their leading comments contain a recognized
native generator header: the Go disclaimer, protobuf's Python disclaimer,
prost's Rust marker, or a CandaceCodegen/Candacegen header in the supported
comment forms. A generated-looking filename alone has no effect. Other generator
names remain non-generated under this inherited policy; this metric is not an
exhaustive detector of all generated artifacts.
Markdown can have a whole-document generated header or validated `csf:diagram`
regions. Region interiors count as generated; boundary markers remain
non-generated. Fenced marker examples remain non-generated. UTF-8, Unicode
whitespace, physical line boundaries, and CRLF handling match the archive
calculator. Generated and non-generated describe explicit markers, never
human-versus-agent authorship, quality, or how much code could be generated.

Every selected entry must name an existing regular file within the root.
Unsafe paths, duplicates, symlink components, invalid SHA-256 declarations,
invalid selected-text UTF-8, and malformed diagram regions fail. Files outside
both corpora still receive path/type/hash-format checks; their contents and hash
changes are outside both metrics, matching the existing archive calculator.
Hash differences are reported, not treated as proof that a receipt is current.

The implementation lives in `generation_metrics.ml` (selection, hashes,
totals, JSON) and `metric_text.ml` (physical lines and marker classification).
For a native caller, the same calculation is available without a subprocess:

```ocaml
let records = Generation_metrics.read_manifest receipt_path in
let report = Generation_metrics.calculate ~root:archive_root records in
let output = Generation_metrics.to_json report in
print_endline (Yojson.Safe.to_string output)
```

`write` and `check` still generate and verify documentation from
`architecture.csf`; `metrics` does neither. The Python calculator shipped in
standalone archives remains available until those consumers have a packaged
native executable. It is a compatibility oracle; the explicit code exclusions
are maintained in both calculators. `metric_parity_test.py` runs its test corpus
against the native command and compares the legacy fields plus both new
percentages. Native fixtures also exercise path rejection, hashes, empty
corpora, headers, and Markdown regions.

```sh
CANDACE_BAZEL_CACHE=/tmp/candace-csf-bazel-cache \
  bash tools/bazel.sh test //csf/compiler/language:tests \
  --test_output=errors --lockfile_mode=error
```

`metric_unicode_cgen.ml` is a checked-in compatibility table derived from
Python 3.12's Unicode 15.0.0 `str.isalnum()` classification plus underscore.
The native test checks that its intervals are valid, ordered, disjoint and
coalesced, verifies both endpoints and their neighbors, and covers representative
BMP and supplementary code points. Updating the table requires an explicit
Unicode-version migration and reviewed compatibility vectors; no host Unicode
database or generated-code step participates in ordinary builds.
