# Zero Is Not Clean: Coverage-Aware Gates and Checkable Artifacts for Operator-Directed Coding Agents

> **Status: agent draft, 2026-10-02, second version.** All prose is unapproved and is the operator's to rewrite or approve (source monorepo issue #379). A number marked † was measured on `candacelabs/csf_staging` at `origin/main` `6ef6762` unless another revision is named, and the Measurements section gives the command for each. Results marked *planned* have not been run. Citations are keys into `docs/paper/keys.txt`; the References section is generated by `docs/paper/checks/bib.py` and is never edited by hand.

## Abstract

A gate that reports zero findings tells you one of two things: the property holds, or the gate never looked. On one day in one live monorepo we found three gates of the second kind: an ontology checker that reported no placement violations while a declared containment claim was violated, a generated-file drift check that reported no drift while two generated copies had drifted, and a shell gate that forbade polling loops while the one session it was never installed in ran one. We call the second kind vacuous, after the model-checking term for a specification satisfied for want of an antecedent [vacuity]. We propose a discipline for coding-agent harnesses in which (1) every gate reports coverage with its findings, so that clean means checked and clean; (2) every gate is written once as a Datalog predicate that generates both its checker and its rendered mathematics; (3) every claim an agent sends is a typed artifact that the receiver re-checks rather than trusts, for example a citation carrying the DOI the receiver resolves, or a measurement carrying the command the receiver re-runs; and (4) architecture diagrams are projections of checked relations, with soundness and completeness stated and enforced. We report the measured state of the repository, a pilot in which eighteen weak-model sessions produced only typed artifacts under schema, and the evaluation the proposal still owes. Of the four claims, the first is measured, the fourth is defined, and the second and third are partly built.

## 1. Introduction

A developer asks an agent for X and the agent produces Y. The gap is usually found by a human reading a diff, and often long after the fact. In our setting one operator directs several agents at once through a harness, and the gap shows up as a repeated correction. For example, the operator wrote "this is the 3rd time we've brought it up as a blocker" about message queueing on 2026-10-02 †, after two earlier requests had been recorded as tickets without a gate.

The motivating failure is concrete. The repository's ontology file defines the term `widget` as "a component of gotth-live ... Widgets exist within gotth-live" (line 34 of `csf/compiler/language/architecture.csf` †). The directory tree places `pkg/widget` (83 files †) beside `pkg/gotth`, and 14 packages import it directly † (for example `services/opsview` and `services/copilot-adapter/kanban`). The ontology checker's placement signal reported six findings that day †, none of them this one. It was not wrong about what it checked: it never extracted the containment claim, so the claim was never in its domain. Its zero meant "not covered".

The same day produced two more zeros of that kind. The drift check reported no drift while `csf/docs/generated/architecture.csf` (362 lines †) disagreed with its source on three terms, because no generator owned that copy and the check only re-ran owned generators. And a shell gate that rejects `until ...; do sleep 1; done` loops in every agent session let one run in the operator's own session, because the hook was never installed there: that session's gate coverage was zero, and a self-matching `pgrep -f` loop that the gate had been written to stop ran again.

This paper makes three arguments, each with its evidence labelled as measured, built or planned.

1. **Coverage belongs in the gate's output** (Section 3). A gate is clean only when its findings are empty *and* every claim in its domain was evaluated. We give the predicate, relate it to vacuity detection, and show that the three escapes above all have coverage below one. Measured.
2. **Gates and diagrams are projections of one source** (Sections 3 and 4). Each gate is one Datalog predicate from which the checker and the LaTeX are generated; each diagram is a projection of checked relations with soundness and completeness as theorems about the projection. The predicates exist; the generation is planned.
3. **Agent output is a protocol of checkable artifacts** (Section 5). An agent sends a citation with its registry key, a measurement with the command that reproduces it, a diff, or a predicate with its falsifier; the receiver re-runs rather than trusts, for example by resolving the DOI or re-executing the command. A pilot with eighteen weak-model sessions shows what this buys and what it does not. Partly built; the pilot is measured.

## 2. Setting

The system under study is CSF, a Go monorepo in which the architecture is declared in a small language, `architecture.csf`, compiled by `csfc` into a glossary, a dictionary, Mermaid diagrams and placement checks. One harness process per machine runs coding-agent sessions, each in its own git worktree, with a hook on every shell command and every commit. On 2026-10-02 the ontology held 124 terms and 10 literature entries †; the repository held 212 Markdown files †; fourteen pull requests merged that day †, all through a merge script that re-runs the checks on the merged tree and refuses a regression.

Two facts about the setting shape everything below. First, the operator is the only human, so operator corrections are the labelled signal. For example, the message "POSTGRES IS NOT A MEMORY STORE" marked a type named `MemoryStore` that wrapped a PostgreSQL store, and became both a rename and a naming rule. Second, agents commit under the operator's account, so authorship cannot distinguish a human line from an agent line; Section 5.3 returns to this.

## 3. Coverage-aware gates

### 3.1 Universe

Let $T$ be the set of ontology terms and $P$ the set of repository paths. Write $p \sqsubseteq q$ for the reflexive-transitive closure of "is a child directory of": $p \sqsubseteq q$ iff $p = q$ or some ancestor of $p$ is $q$. Let $F \subseteq P$ be the tracked source files. Two partial functions and one relation are extracted from the repository and the ontology:

- $\mathrm{home} : T \rightharpoonup P$, the directory a term declares as its own. It is partial: on 2026-10-02, 64 of 124 terms declared none †.
- $\mathrm{own} : F \to T$, the term that owns a file, by package.
- $W_0 \subseteq T \times T$, the direct containment claims, where $(x, y) \in W_0$ iff $x$'s definition says $x$ exists within $y$. Let $W = W_0^{+}$ be its transitive closure, so that a widget inside a live view inside gotth-live is checked against gotth-live too.

### 3.2 The gate

$$G \coloneqq C_0 \wedge C_1 \wedge C_2 \wedge C_3$$

$$C_0 \coloneqq \forall t \in \mathrm{terms}(W).\; t \in \mathrm{dom}(\mathrm{home}) \vee \mathrm{planned}(t) \qquad\text{(a contained term has a home or is declared planned)}$$

$$C_1 \coloneqq \forall (x,y) \in W.\; \mathrm{home}(x) \sqsubseteq \mathrm{home}(y) \qquad\text{(containment)}$$

$$C_2 \coloneqq \forall f \in F.\; \mathrm{own}(f) \in \mathrm{dom}(\mathrm{home}) \Rightarrow f \sqsubseteq \mathrm{home}(\mathrm{own}(f)) \qquad\text{(placement)}$$

$$C_3 \coloneqq \forall t \in T.\; \bigl|\{p : p \text{ declared as home of } t\}\bigr| \le 1 \qquad\text{(single source)}$$

For the widget case, $(\mathit{widget}, \mathit{gotth\_live}) \in W_0$, $\mathrm{home}(\mathit{widget}) = \texttt{pkg/widget}$, $\mathrm{home}(\mathit{gotth\_live}) = \texttt{pkg/gotth/live}$, and $\texttt{pkg/widget} \not\sqsubseteq \texttt{pkg/gotth/live}$, so the pair is a $C_1$ finding.

### 3.3 Claims, coverage, clean

Each clause quantifies over a set; that set is the clause's claims. $\mathrm{claims}(C_1) = W$, $\mathrm{claims}(C_2) = F$, $\mathrm{claims}(C_3) = T$, $\mathrm{claims}(C_0) = \mathrm{terms}(W)$. A claim is checked when the evaluator actually evaluated its clause body on it, which fails when an input is missing: for example, $C_1$ on a pair whose $\mathrm{home}$ is undefined.

$$\mathrm{cov}(C) = \frac{|\mathrm{checked}(C)|}{|\mathrm{claims}(C)|}, \qquad \mathrm{clean}(G) \iff \mathrm{findings}(G) = \emptyset \;\wedge\; \forall C \in G.\; \mathrm{cov}(C) = 1$$

The three escapes have the same shape. The placement checker evaluated $C_2$ over $F$ and reported six findings, but $W$ was never extracted, so $\mathrm{cov}(C_1) = 0$ and $C_1$ held for want of a domain. The drift check evaluated owned generators and skipped the orphaned copies, so its coverage over generated files was below one. The shell gate's coverage over sessions on the host was below one. In model checking this is vacuity: a formula such as $AG(\mathit{req} \to AF\,\mathit{ack})$ holds in a model where $\mathit{req}$ never occurs, and vacuity detection reports that the antecedent did no work [vacuity]. Our $\mathrm{cov} < 1$ is the same condition stated for a universally quantified clause over extracted facts: the quantifier did no work because the domain was empty or partial. The difference is in what is reported: vacuity detection reports a vacuous formula, whereas we report a ratio, so that, for example, a checker that evaluated 97 of 100 containment claims reports $\mathrm{cov} = 0.97$, and one that extracted no claims reports $0$, where vacuity detection would report only the second.

**Proposition (coverage by construction).** If $W_0$ is extracted from a typed relation declared in the same source the evaluator reads, and $C_0$ holds, then $\mathrm{cov}(C_1) = 1$. *Sketch.* The evaluator enumerates $W$ from the declaration, so $\mathrm{claims}(C_1)$ is exactly the set it iterates; $C_0$ guarantees both homes are defined for every pair, so every body evaluates. The widget escape happened because $W_0$ was prose, not a relation; the fix is a typed `within` field, not a smarter extractor.

### 3.4 Single source: the predicate generates the checker and the mathematics

Each clause above is also a Datalog rule. For $C_1$:

```prolog
under(P, P)  :- dir(P).
under(P, Q)  :- parent(P, R), under(R, Q).
c1_violation(X, Y) :- within(X, Y), home(X, HX), home(Y, HY), not under(HX, HY).
```

Datalog with stratified negation and counting evaluates such rules over finite facts and always terminates [datalog]; the same machinery underlies industrial code-query systems [ql] and whole-program analyses [doop, souffle, bddbddb]. Our use differs from theirs in the relations, not the engine. For example, Doop's facts are call edges and heap allocations and its queries compute points-to sets; our facts are `within`, `home` and `parent` and our queries compute placement violations. We reuse an existing evaluator rather than write one; for example, the repository's compiler contained three hand-written relational checks (a dependency-cycle check, a transitive-ownership check and a same-process check), each a few lines of Datalog, and a session is migrating them onto the evaluator and deleting the hand-written traversals †.

The intended discipline is that a gate is declared once, in the ontology language, and two artifacts are generated from that one syntax tree: the Datalog program the evaluator runs and the LaTeX a reviewer reads. The mathematics in this paper was written by hand; that is the state to be removed, not the state to be documented. Why-provenance gives each derived violation the set of base facts that produced it [provenance], which is the proof trace Section 5 relies on. *The generation step is planned.* Next step to try: declare $C_1$ once as a `gate` block in the ontology language, emit the Datalog rule above and this LaTeX from its syntax tree, and pin both with a golden test; the evaluator the migration session chose is the back end.

### 3.5 The merge ratchet

For a base revision $b$, a head $h$, signals $S$ with weights $w$ and a blocking subset $B \subseteq S$:

$$\mathrm{refuse}(b,h) \iff \exists s \in B.\; c_s(h) > c_s(b) \;\lor\; \sum_{s \in S} w_s c_s(h) > \sum_{s \in S} w_s c_s(b) \;\lor\; \exists s.\; \mathrm{cov}_s(h) < \mathrm{cov}_s(b)$$

The first two disjuncts exist on `main` as `tools/merge-pr.sh`; the third is the addition this paper argues for, and it is planned. The ratchet's first run was on its own pull request, which it refused because an absolute house-lint check met six pre-existing findings on `main` †; the pull request was then merged by hand. Its second day of use went better: it refused a README change whose only defect was four ontology terms used without links to the dictionary (unlinked terms 739 to 743 †), which is the kind of regression a human reviewer does not see.

## 4. Diagrams as projections

Let $R_i^{\mathrm{checked}}$ be the facts of relation $i$ that passed their gate. A diagram is $D = (N, E, \ell)$ with $E = \{(x, y, i) : (x, y) \in R_i\}$ and $\ell(x,y,i) = i$. Then

$$\mathrm{sound}(D) \iff E \subseteq \textstyle\bigcup_i R_i^{\mathrm{checked}}, \qquad \mathrm{complete}(D, S) \iff \pi_S\bigl(\textstyle\bigcup_i R_i^{\mathrm{checked}}\bigr) \subseteq E$$

where a view is a projection $\pi_S$ onto a node set $S$ and a relation subset, and completeness is relative to the view's declared scope: a view that shows only `depends_on` is not incomplete for omitting `communicates`. Projections preserve soundness because they only remove edges.

This is the software reflexion model of Murphy, Notkin and Sullivan [reflexion-models, reflexion-models-tse] applied to a declared ontology. They took a high-level model drawn by an engineer and a map from source entities to model entities, and reported convergences, divergences and absences; their worked example mapped a Unix virtual-memory implementation to a nine-box design. We take the model from the ontology's typed relations and the map from $\mathrm{home}$ and $\mathrm{own}$, and our divergences are $C_1$ and $C_2$ findings. Two things are added. The coverage ratio says how much of the model was mapped at all, where a reflexion model reports only on what was mapped. And the diagram is generated from the checked facts rather than drawn; for example, today the repository's four diagrams are rendered by the compiler from 81 hand-declared node, edge and group lines †, none of which is compared to code, so an edge can be drawn between two services that never communicate. Re-deriving them from facts yields the first set of spurious edges (drawn but false) and omitted edges (true but undrawn). *Planned.* Next step to try: run the diagram's edge set against the `depends_on`, `communicates` and `within` facts the migrated checker already extracts, publish the two difference sets as the first measurement, and only then replace the 81 lines with a `show` declaration.

## 5. Agent output as a protocol

### 5.1 Artifact kinds

An agent's deliverable is one of five typed artifacts; prose may annotate an artifact and never stands alone.

| kind | required fields | example from the pilot |
|---|---|---|
| check | script path that exists, exit code, an excerpt it fails on | `prose-lint.py`, exit 1 on "they are noisy" |
| predicate, theorem, conjecture | LaTeX statement, what refutes it, status | $W \coloneqq W_0^{+}$ with status "ill-formed in draft", refuted by a nested containment the base relation misses |
| diff | unified diff against a named file at a revision | a rewrite of one contrastive sentence |
| citation | DOI or arXiv id, verified flag, the verify command, relation to our work, one example of theirs and one of ours | Reflexion, `diverges`, verified by `curl export.arxiv.org/...` |
| measurement | value, the command that reproduces it, revision | `212` Markdown files, `git ls-tree -r --name-only origin/main \| grep -c .md$` |

### 5.2 Obligations on sends

Three rules attach to the act of replying, in the way advice attaches to a join point [aop]. First, an assertion of a connection between two things must be followed in the same or the next turn by an artifact naming both, or by a typed decline with a reason. For example, an agent that writes "this is the ANSI/SPARC split" owes a literature row for ANSI/SPARC before its turn ends. Second, a contrastive sentence must name both sides and give an example of each. For example, "our miners differ in what they target" without saying what the other side targets is refused, and the version that names Reflexion's target (the agent's next prompt) and ours (the repository's gates) passes. Third, a measurement carries its command and a citation its key, so the receiver can re-run it; for example, the Markdown count in Section 6 carries its `git ls-tree` command.

These are the shape of an agent communication language. KQML and FIPA-ACL typed messages by speech act, with preconditions on the sender's beliefs: an `inform(φ)` was legal only if the sender believed φ [kqml, acl-landscape]. Our types are artifacts, and the precondition is a registry or a repository: a `citation` is legal only if the DOI resolved. Session types make the protocol a type, so that a program that sends the wrong message next does not compile [session-types, multiparty]; our "after an assertion, only an artifact or a decline" is a session type over turns, enforced by a hook rather than a compiler. Proof-carrying code ships a proof with the code so the receiver checks cheaply [pcc]; our `measurement` ships the command, and the operator re-runs it instead of trusting the number.

### 5.3 Provenance

Every span of a document is classified by origin, never by declaration: $\delta$ if it equals a committed generator's output on committed inputs, $\eta$ if it is a signed human line from a human-owned directory, $\sigma$ otherwise. A composition $f(x_1, \ldots, x_n)$ is $\delta$ when $f$ is deterministic and every $x_i$ is $\delta$ or $\eta$; $\sigma$ absorbs. The distinction follows PROV-DM's Person and SoftwareAgent [prov-dm] and Knuth's view of a document as a build artifact [knuth84]: in WEB, the printed program and the compiled program came from one source, and here the References section and the measurement lines come from generators whose output the composer re-checks byte for byte.

Run on the first version of this paper †, the composer classified 47 spans: $\delta$ 0%, $\eta$ 0%, $\sigma$ 100%, and all 47 unresolved, because the commit that introduced them carried no session or model trailer and so could not evidence even $\sigma$. The fix was a commit trailer, not a sentence. In this version the References block and the ghost-term measurement are $\delta$ by construction, because they are the generators' output; for example, the References section below is the stdout of `bib.py` over `keys.txt`, and the composer re-runs `bib.py` and compares bytes. $\eta$ remains 0: there is no human-owned directory with a signed commit yet, and agents commit under the operator's account. Next step to try: a `humans/` directory whose commits are signed with the operator's key and carry no session trailer; the first signed line quoted into this paper becomes its first $\eta$ span, and the composer's output is the proof.

### 5.4 Pilot: eighteen weak-model sessions under schema

To test whether structure, rather than model strength, makes agent output usable (for example, whether a schema with no free-text field keeps a small model from returning prose findings), we ran the review of this paper's first version as eighteen sessions of the smallest available model †, with schemas that had no free-text findings field: a critic could return checks, formal statements, diffs, citations and measurements, and nothing else. The run took 470 s, 293 tool uses and 1.28 M tokens †. It returned 15 formal statements, 21 diffs, 14 measurements and 48 distinct citation keys †.

What survived independent re-checking:

- Of 48 citations self-reported as verified, 42 were confirmed by an independent script, one carried a wrong title (a 2010 conformance-checking overview rendered with another work's title), and five were unreached by the re-check itself, two because the DOIs are registered with DataCite and the re-check queried only Crossref †. One key had been copied from a wrong DOI in the prompt, so the agent reproduced the author's error; only the generator-based check caught it.
- Two formal corrections were right and are adopted above: $W$ must be a closure, and `claims` must be defined for coverage to mean anything.
- One check script reported 7 of 7 citations passing while printing an arXiv feed title ("arXiv Query: ...") for two of them and passing a third that had no URL at all †. The vacuous pass of Section 3 reproduced itself inside the review of the paper about it.
- The same work received relation `diverges` from one session and `same_as` from another, and one session labelled a prose finding as a `check` with a script path that did not exist †.

The reading is narrow. Artifacts whose validity is mechanical (a key resolves, a command prints a number) were right or verifiably wrong, and the wrong ones were caught by re-running. Artifacts that encode a judgment were wrong often enough that each needs a mechanical check behind it; for example, the same work was labelled `diverges` by one session and `same_as` by another, and a measurement of "citation pass rate 7/7" was marked as agreeing with the record when two of the seven passes were vacuous. Structure made the output checkable; it did not make it correct.

## 7. Related work

Architecture conformance checking is an established area; the overview by Passos and colleagues compares dependency-structure matrices, source-code query languages and reflexion models [conformance-overview], and Knodel and Popescu compare static compliance approaches [conformance-comparison]. Those tools check a model an engineer drew against code an engineer wrote. For example, a reflexion model reports that a `pager` module calls `disk` where the design drew no arrow. We check a model agents are extending against code agents are writing, so the model itself is under version control and under the same gate, and the operator's corrections are the labels: for example, the ruling "memory means physical RAM, not in-process state" became a retired-vocabulary signal the same day.

Agent self-improvement work changes the agent. Reflexion feeds an agent a verbal account of its own failure so that its next attempt improves; for example, a failed unit test becomes the sentence "the loop bound was off by one" in the next prompt [reflexion]. DSPy compiles a declarative pipeline of language-model calls and optimizes its prompts and demonstrations against a metric [dspy]. Clover checks that code, its docstring and its formal annotations agree, using a verifier for the code and a model for the prose [clover]. SWE-agent designs the interface through which an agent reads and edits a repository [swe-agent]. Our loop changes the repository's gates rather than the agent; for example, the miner that finds an unshown contrast emits a hook that refuses the next one, and the model is unchanged. Clover is the closest in spirit, and the difference is what is kept consistent; for example, Clover keeps one function's code, docstring and annotations consistent with each other, while we keep an ontology, a directory tree, the diagrams and the documents consistent with one another across a repository.

Backtesting a rule on a historical record overstates its performance when the rule's parameters were fitted on that record; the finance literature names this backtest overfitting and gives the probability of it under multiple trials [backtest, backtest-pbo]. Our acceptance rule for a mined gate fits its threshold on records before a time $t$ and accepts only on records after $t$, which is walk-forward evaluation for time-ordered data [walk-forward]. The first version of that rule in our tickets was in-sample, and it was the literature lookup that corrected it.

Operator affect is proposed above as a priority signal. Off-the-shelf sentiment tools perform poorly on software-engineering text; for example, "kill the process" reads as negative and "this is sick" as positive to a general-domain model [sentiment-se]. We therefore treat affect as a candidate feature that must be validated against labelled events, such as the day's fourteen operator messages with known targets, before it can set priority.

The data model underlying stores and data structures follows the ANSI/SPARC three-level architecture, where the conceptual schema is independent of the internal one [ansi-sparc], and Codd's physical data independence [codd]: a graph data structure placed by a memory store today and a PostgreSQL store tomorrow does not change the code written against the graph. Hooks on service actions follow aspect-oriented programming's advice on join points [aop]. Intention as a first-class object in the protocol follows Cohen and Levesque [intention].

## 8. Threats to validity

The study covers one repository, one operator and one day, and the system under study produced this report, with the agent that wrote it also the one whose offenses it describes. The agent-side pilot used one model, eighteen sessions and one task; its framing stage anchored on the first draft, with all four candidate framings reusing the first draft's title phrase, and one wrong DOI in a prompt propagated into an agent's output. Two headline numbers are unreceipted. The operator's corrections, used as labels throughout, are one person's judgment, and the affect signal built on them is unvalidated. Finally, "everything is generated" is a direction: the measured upper bound on generated bytes in the repository is 11.6% †, and every section of this paper except the References and one measurement line is agent prose awaiting approval.

## 9. Conclusion

A zero from a gate is a claim about a domain, and the domain is the part most often missing. Reporting coverage next to findings, declaring each gate once and generating its checker and its mathematics, treating every agent claim as an artifact the receiver re-runs, and generating diagrams from checked relations are four forms of the same rule: do not let a checker, a diagram or an agent assert what it did not compute. The repository measured here is some distance from that rule, and the distance is now a number.
