# INBOX: Agents are Goroutines with Inboxes

## Implementation Summary

This slice delivers five core components for enabling agents to be interrupted mid-turn via inbox messages:

### 1. Queue Ordering with (Priority, Sequence) Key
- **Location**: `services/harness/sessions.go` - queuedMessage struct
- **Change**: Added `sequence uint64` field to track message arrival order
- **Implementation**: `sessionRecord.nextSeq` counter incremented on each Send
- **Proof**: the `the inbox` spec that gives every message its own receipt and a rising sequence, in `services/harness/sessions_test.go`, validates sequence assignment and the interrupt-first listing

### 2. Stable Message IDs
- **Location**: `services/harness/sessions.go` - Send method
- **Change**: UUID receipt IDs are already stable; sequence numbers provide (priority, sequence) ordering
- **Proof**: the `the inbox` specs that give concurrent senders distinct receipts and move a message without changing its receipt verify unique IDs remain unique through send and move/top operations

### 3. Queue Operations: list, move, top
- **Location**: `services/harness/sessions.go` - ListInbox, MoveInboxMessage, TopInboxMessage methods
- **Definitions**: Proto messages in `proto/candace/harness/v1/harness.proto`
- **list**: `ListInbox()` returns all queued messages with timestamps
- **move**: `MoveInboxMessage()` reorders message to specified index
- **top**: `TopInboxMessage()` promotes message to front of queue
- **Proof**: the `the inbox` spec that moves a message to an index and to the top demonstrates both operations

### 4. Priority Send Interrupts Running Turn
- **Architecture**: ClaudeCodeSession.Inject() writes user message to stdin
- **Integration point**: Will be called from `services/harness/sessions.go turn()` method
- **Status**: Infrastructure in place; executor integration in next slice
- **Stub executor**: `services/harness/session/stub_test.go` records Inject calls for testing

### 5. Read Receipts
- **Location**: `services/harness/sessions.go` - sessionRecord.deliveredMessages map
- **Tracking**: Maps receipt_id → time.Time for delivery latency measurement
- **State transitions**: QUEUED (on Send) → DELIVERED (on Inject) → READ (on display) → ANSWERED (on return)
- **Proof**: the `the inbox` spec that stamps a receipt with the service clock's instant checks the QUEUED stamp; no spec measures the time from Send to delivery yet
